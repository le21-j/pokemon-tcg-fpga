# Competition and training-data research

Checked October 29, 2026. This note distinguishes documented interfaces from data that has actually been inspected.

## Verified

- The requested URL identifies the original Simulation competition, whose entry period has ended. Agents competed through automated matches and a skill-rating leaderboard. The separate [Playground description](https://www.kaggle.com/competitions/the-pokemon-company-ptcg-ai-battle-challenge-playground/overview/description) calls Playground a continuation and explicitly specifies best of three. Its listed submission deadline is January 8, 2027. The original page contains inconsistent historical deadline wording, so this note does not use it as a scheduling reference. [Original organizer rules and schedule](https://ptcg-abc.pokemon.co.jp/?lang=en)

- The current official environment distinguishes the legacy engine from the newer environment. `version=1` always plays BO1. The current defaults are `version=2` and `bo=3`. Training samples, card metadata, evaluation runs, and model exports therefore need an explicit environment version. This establishes a compatibility boundary, not proof that old replays match Playground. [Official cabt configuration](https://github.com/Kaggle/kaggle-environments/blob/998b15c14b1b77aafb1843bed63858455035affd/kaggle_environments/envs/cabt/cabt.json#L7-L22)

- This is an agent-development task. Each decision supplies an observation with `logs`, `current`, and `select`. The agent returns a list of indices into `select.option`. Initial deck selection has `current=None` and `select=None`; the official baseline returns 60 card IDs at that point. Opponent hand identities are hidden, and face-down prizes are `None`. Logs contain events since the previous selection, so a single observation need not contain the entire history. [Observation guide](https://matsuoinstitute.github.io/cabt/#observation-structures), [Observation reference](https://matsuoinstitute.github.io/cabt/api.html#api.Observation), [official baseline](https://github.com/Kaggle/kaggle-environments/blob/998b15c14b1b77aafb1843bed63858455035affd/kaggle_environments/envs/cabt/cabt.py)

- `select.minCount` and `select.maxCount` bound the number of selected options. The minimum can be zero. The interface supports several selections and has a `SKILL_ORDER` context for activation order. A policy that always returns one argmax is insufficient. A host adapter must respect the selection context, cardinality, and ordering semantics. The Python wrapper forwards the supplied index list to the native engine without sorting it. [SelectData and selection contexts](https://matsuoinstitute.github.io/cabt/api.html#api.SelectData), [selection wrapper](https://github.com/Kaggle/kaggle-environments/blob/998b15c14b1b77aafb1843bed63858455035affd/kaggle_environments/envs/cabt/cg/game.py#L52-L68)

- The original Data page was inspected in the browser. It lists English and Japanese card metadata CSVs, card-reference PDFs, `ptcg_engine`, and `sample_submission`, with 60 files totaling 327.59 MB. The described CSV fields cover card identity, expansion, stage, category, rules, HP, type, weaknesses, resistance, retreat, and move name, cost, damage, and effect text. These are card-reference and development assets, not a verified table of demonstrated decisions. File previews and downloads require sign-in and acceptance of competition rules. [Original Data page](https://www.kaggle.com/competitions/pokemon-tcg-ai-battle/data)

- That Data page also describes replay access through Submissions for one's own episodes, Leaderboard for other teams, and the CLI. It promises daily top-episode exports through the forums; actual export availability was not verified. The official CLI supports downloading episode JSON. CABT also exposes card and attack metadata through `all_card_data()` and `all_attack()`. [Original Data page](https://www.kaggle.com/competitions/pokemon-tcg-ai-battle/data), [official replay-download documentation](https://github.com/Kaggle/kaggle-cli/blob/main/docs/simulation_competitions.md#7-download-an-episode-replay), [CABT metadata APIs](https://matsuoinstitute.github.io/cabt/#sim-module)

- Local simulator matches can generate training trajectories. The documented example runs `make("cabt", ...)` and `env.run([agent, agent])`. The environment serializes `steps`, configuration, and rewards. CABT's replay construction pairs the active player's observation at step `t` with actions from step `t+1`, and stores visualization data separately. Preserve decision order and player identity when extracting examples. [Local match example](https://matsuoinstitute.github.io/cabt/#example-test-script), [environment serialization](https://github.com/Kaggle/kaggle-environments/blob/998b15c14b1b77aafb1843bed63858455035affd/kaggle_environments/core.py#L515-L543), [CABT replay construction](https://github.com/Kaggle/kaggle-environments/blob/998b15c14b1b77aafb1843bed63858455035affd/kaggle_environments/envs/cabt/cabt.py#L88-L109)

## Unverified and access limits

- No Pokémon TCG data files were found in this workspace. At the start of this check, `project/` contained only `README.md`; the CSV files elsewhere belong to coursework. The user's available data refers to Kaggle's competition assets, not an inspected local training dataset.
- The public web reader returned no readable Data-page body; the asset facts above came from direct browser inspection by the coordinating agent. No authenticated account, accepted competition rules, or downloaded records were inspected. CSV row counts, bundled SDK versions, public episode export contents and dates, and Playground's exact downloadable inventory remain unverified. [Playground Data page](https://www.kaggle.com/competitions/the-pokemon-company-ptcg-ai-battle-challenge-playground/data), [Kaggle-hosted original episodes index](https://www.kaggle.com/datasets/kaggle/pokemon-tcg-ai-battle-episodes-index)
- No downloaded replay was sampled. The source supports recovering legal choices and selected indices from source-generated episodes, but a public dataset's actual schema, completeness, and version still need verification. Replay visualization or search payloads may expose information unavailable to the acting player. Training features must come from the player-visible observation and permitted history, with privileged fields excluded after an actual replay audit.
- Multiple-choice dependency rules, repeated-index legality, and every order-sensitive context have not been verified against native engine behavior. Nor has the exact card-pool difference between original and Playground assets. Pin the target SDK and exercise these cases before fixing model output shapes or FPGA buffer limits.

## Architectural consequence

Use the host for simulator interaction, observation history, candidate encoding, and valid selection assembly. A small FPGA model can score the current legal options. This split follows the verified variable-length choice interface. Start with locally generated trajectories if suitable downloaded demonstrations cannot be verified, and evaluate complete games as well as imitation agreement.
